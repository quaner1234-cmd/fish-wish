## 2. 讨论起点（**不是决定，不是官方要求，未经评估**）

以下只是与 Kiro 开始讨论时可用的提问角度。任何一条都要经 Alex 确认才成为方向。

1. **「诡异」能否本身就是功能？** 例如把文字输入、打字动画、叙事节奏做成应用的核心交互，而不是给普通 App 套一层暗色皮肤。——对应 L1 / L2 / L5。
2. **影视/游戏的叙事机制能否成为可运行 App 的主循环？** 若有，它解决谁的什么问题？——对应 L2 / L4 / L7（Potential Impact 20%）。
3. **是在 `Stranger Typing` 基础上延展成完整产品，还是另起？** 若延展，需按规则披露既有代码（规则 §New Projects Only；且项目须 2026-10-30 之后新建）。——对应 L5 与 [1]。
4. **如何用 spec-driven development 组织这个作品？** Kiro 的 spec 三阶段为 `requirements.md` → `design.md` → `tasks.md` [3]；steering 由 `.kiro/steering/` 提供 [4]。这同时关系到 D-09（how Kiro was used 说明）。

> 注意：官网 Build Session 的示例是「幽灵主题浏览器游戏」(L6)，但**官方并未限定 Costume Contest 必须是游戏或网页**；规则原文是 "Build any app" [1][2]。不要把示例当成限制。

## 3. 评估维度（供后续给候选方向打分，直接对应评审标准 [1]）

| 维度 | 权重 | 评估问题 |
| --- | --- | --- |
| 真实功能 | 硬性 | 能否安装并稳定运行？功能是否与描述/视频一致？ |
| 界面（诡异 + 精致 + 难忘） | Design 20% | 诡异元素是否**增强功能**？是否完整、连贯、有意图，而非 demo 贴皮？细分见下方 3.1 |
| 真实问题 / 真实受众 | Potential Impact 20% | 谁会用？解决什么？ |
| 新颖度 | Innovation 20% | 与既有概念有何不同？ |
| 可演示性 | Presentation 20% | 能否在 < 3 分钟视频里端到端演示清楚？ |
| Kiro 使用深度 | Technological Implementation 20% | 是否用到 specs / steering / hooks / agents / MCP 等，并有策略？ |
| 可行性 | 内部 | 距 2026-12-04 14:00 PT 约 3 周，4,000 credits 是否够用（Q-02 / Q-05） |

### 3.1 "诡异界面"自检四条（Kiro 的解读，不是官方规则）

1. **诡异元素承担功能**：去掉它，某个功能就失效。只换皮（南瓜、紫橙配色、恐怖字体）不算。
2. **恐怖来自"不对劲"**：先正常，再逐步破坏；克制优于堆特效。
3. **细节一致**：单一世界观；动效有节奏；声音有静音开关并处理自动播放限制；加载 / 空状态 / 报错也在主题里；不掉帧；对比度、可读性、`prefers-reduced-motion` 不打折扣。
4. **一个难忘瞬间**：10 秒内看懂、想分享，放在演示视频开头。
