# Requirements Document — 人面鱼纹盆互动体验（工作名 `urn-experience`）

> 状态：v0.5，2026-11-22。v0.3 改为故事向（D-007）：那张脸对用户说话，台词是虚构；史实集中到结尾的 "What is real" 页。v0.4：开头不放说明与内容提示，"inspired by" 移到结尾卡片（D-008）；第四幕加动画和母亲的剪影（D-010）。v0.5：去掉配音，台词只用字幕（D-012，撤销 D-009）；第一幕的光从盆上的小孔进入瓮里，瓮里的光是"你"（D-013）。变动的条目标了 [v0.3] / [v0.4] / [v0.5]。
> 方向与基调见 `decisions/DECISIONS.md` D-003 / D-004；史实依据见 `context/research-urn-burial.md`（下文用 F# 引用）。
> 作品名暂定 "Fish Wish"（D-007）；spec 目录仍用工作名 `urn-experience`。界面里的名称只在一处定义。

## Introduction

一个在浏览器里运行的短篇互动叙事体验，3–5 分钟。用户在黑暗中发掘出一个约 6000 年前的婴儿瓮棺，进入瓮内，看到盆内壁画着的一张脸；随后通过小孔、地面上的房子，明白这是父母留给孩子的东西。最后用户再看一次同一张脸。

基调（Alex 原话）："我希望留下的是爱，恐怖是形式是工具，不是目的。"

[v0.3] 叙述者是盆上那张脸：它把用户当成瓮里的那个孩子，对"你"说话。母亲、父亲、孩子和脸的话都是虚构的，[v0.4] 在结尾卡片和 "What is real" 页写明。它不是有输赢、关卡和分数的游戏。诡异元素（黑暗、只照亮一小块的灯、那张脸、小孔里的光）决定用户能看到什么、什么时候看到，从而推动叙事。

**目标用户**：对历史、博物馆、考古有兴趣的普通人，包括不了解中国文化的人；以及 Kiroween 评委。
**不做**：账号、后端、数据收集、多件文物、关卡制游戏。

## Glossary

- **体验 / Experience**：本作品，整个网页应用。
- **灯 / Lamp**：跟随指针（或键盘）移动的一小块光，是用户唯一的光源。[v0.5] 第一幕里它是挖土人的灯；它从小孔进到瓮里以后，变成更小、更稳、不像火苗的光，就是"你"（D-013）。
- **小孔 / Hole**：盆上的一个小孔（F8）。第一幕从上面看得到，第二、三幕从下面看得到，是同一个孔。
- **盆**：人面鱼纹彩陶盆，在作品里扣在瓮口当盖子。
- **瓮**：装孩子的陶罐。
- **幕 / Scene**：体验的五个段落：发掘、入瓮、小孔、升起、再看。
- **说法 / Reading**：学界没有定论的解释；在 "What is real" 页必须标明是 "一种说法"。
- **故事句 / Story line**：脸说的话，虚构，不需要出处。
- **史实句 / History line**："What is real" 页和结尾卡片里的句子，必须有出处。
- [v0.5] 那张脸没有录音，只用字幕说话，下面配一声很轻的合成气声（D-012）。

## Requirements

### Requirement 1：开场与灯

**User Story:** 作为用户，我想在一片黑暗里只靠一盏灯去看，这样我会小心、好奇，带着一点不安进入故事。

#### Acceptance Criteria

1. [v0.4] 当用户打开体验时，系统应显示一个开始画面，包含作品名、一行副标题、声音说明、操作说明和"开始"按钮；不放项目说明和内容提示（D-008）。
2. 当用户按下"开始"后，系统应进入全黑画面，只有灯照到的区域可见。
3. 在桌面端，灯应跟随鼠标指针；在触屏端，灯应跟随手指；在仅用键盘时，方向键应能移动灯。
4. 灯的照亮范围应有柔和的边缘，范围外的内容不可见。
5. 当用户超过 10 秒没有操作时，系统应给出一个不打断画面的轻提示（例如远处一点微光），引导下一步。

### Requirement 2：第一幕 发掘

**User Story:** 作为用户，我想亲手刷开泥土，自己发现那个瓮，这样后面的情绪是我自己挖出来的。

#### Acceptance Criteria

1. 当处于发掘幕时，系统应把画面显示为泥土层；用户在灯照范围内按住拖动（或按住键盘确认键），应刷开泥土露出下面的内容。
2. 被刷开的区域应保留，不会重新被泥土盖住。
3. 当瓮口和倒扣的盆露出的面积达到设定阈值时，系统应停止刷土交互。[v0.5] 脸说完本幕最后一句后，盆上的小孔应出现一点缓慢呼吸的微光；用户把灯停在孔上约 1 秒，或微光出现 8 秒后仍没有停上去，灯应移到孔上、变小、熄进孔里，镜头同时推近小孔，然后进入第二幕（D-013）。
4. 发掘幕不应出现人骨或遗体画面。
5. 发掘幕应能在 60 秒内完成；如果用户 90 秒还没完成，系统应自动刷开剩余部分并继续。
6. [v0.5] 盆从上面看应能看到小孔；它与瓮内看到的小孔是同一个，位置左右镜像（从上往下看与从下往上看，左右相反）。

### Requirement 3：第二幕 入瓮与那张脸

**User Story:** 作为用户，我想从瓮里往上看，在黑暗中慢慢看到一张画出来的脸，这是全片最让我发毛的时刻。

#### Acceptance Criteria

1. 当进入第二幕时，系统应把视角转为第一人称，从瓮内向上看，四周是瓮壁，整体近乎全黑。[v0.5] 第二幕应从小孔开始：镜头先贴近同一个孔，再往后拉到整个盆底；光从孔里出来，在用户移动前停在孔边，用户一动，光就慢慢移到指针处（D-013）。
2. 用户移动灯时，应只能照亮盆内壁的一部分；那张脸应随着用户的照射被逐步看清，而不是一次性弹出。
3. 系统不应使用突然的巨响、闪白或跳出式惊吓（jump scare）。不安感应来自黑暗、慢速揭示和声音。
4. 那张脸的纹样应符合 F2（圆脸、头顶尖状物与鳍形装饰、嘴边和耳边的鱼），且全部为自绘，不使用博物馆照片。
5. [v0.3] 当灯第一次照到那张脸时，脸应开口说第一句话（"There you are."）；脸的大部分被照亮后，脸应继续说出它是为谁、由谁画的。
6. [v0.5] 瓮里没有别的光源。第二、三幕里的光应比第一幕的灯小、更稳、暖色更淡，让人看出它已不是那盏油灯（D-013）。

### Requirement 4：第三幕 小孔

**User Story:** 作为用户，我想发现盆上的小孔透进来的一点光，并知道有人特意留了这个孔。

#### Acceptance Criteria

1. 当第三幕开始时，系统应在盆上脸的旁边显示一个透光的小孔。[v0.5] 这就是第一幕光进来的那个孔；第一幕已把土刷开，所以晨光能从孔里透进来。
2. [v0.3] 当用户把灯移到小孔上时，脸应讲出小孔的来历，并把两种学界说法（F9）讲成母亲和父亲各自的愿望。
3. [v0.3] 两种说法在 "What is real" 页标为 "One reading / Another reading"，不应写成定论。
4. 文字显示后，系统应在用户确认或停留一段时间后进入第四幕。

### Requirement 5：第四幕 升起

**User Story:** 作为用户，我想看到这个瓮埋在哪里，从而明白父母把孩子留在了身边。

#### Acceptance Criteria

1. 当第四幕开始时，视角应从瓮内穿过小孔或土层向上升起，到达地面。
2. 地面画面应显示瓮埋在一座房屋旁边；远处应能看出另有一片墓地。
3. [v0.3] 脸应讲出孩子没有被送去村外大人的墓地，而是留在了门边（依据 F5、F14）。
4. 本幕的光线应比前面三幕更暖、更亮，标志情绪从不安转向爱。
5. [v0.4] 本幕的画面应是活的：火塘的火光闪动，烟被风吹到罐子上方，草随风摆，太阳慢慢升起；动画在 `prefers-reduced-motion` 下应减弱（D-010）。
6. [v0.4] 本幕应出现母亲的剪影：她在火塘边添火，然后走出门，跪到罐子旁边。台词说完、她跪下后，才提示继续。

### Requirement 6：第五幕 再看一次

**User Story:** 作为用户，我想再看一次那张脸，发现它一点没变，变的是我。

#### Acceptance Criteria

1. 当第五幕开始时，系统应再次显示第二幕中的同一张脸，纹样不应有任何改动。
2. [v0.3] 本幕的光线和声音应是温和的；脸的话应落在爱上，并用它闭着的眼睛（F2）完成反转。纹样含义无定论（F10）写在 "What is real" 页。
3. [v0.4] 最后一句台词之后，系统应显示结尾卡片：逐行出现 "A story inspired by a 6,000-year-old basin from Banpo, China." / "The people are imagined." / "The basin is real."，之后再提供"重新体验"和"资料来源"两个入口。点击或按键应能立即显示全部。
4. [v0.5] 最后一句台词开始后，脸嘴边衔着的四条小鱼应先亮起来，然后各有一条光做的鱼离开，沿着盆慢慢绕圈，一直游到结尾卡片后面。盆上画的鱼留在原处，纹样不变（R6.1）。不加台词。reduced-motion 下游得更慢、尾巴摆得更小（D-014）。

### Requirement 7：事实与来源

**User Story:** 作为用户和评委，我想知道哪些是史实、哪些是推测，这样我能信任这个作品。

#### Acceptance Criteria

1. [v0.4] 每一句史实句都应能对应到 `context/research-urn-burial.md` 中的一条 F#。结尾卡片应写明 "The people are imagined. The basin is real."（R6.3）。
2. 标为"不上屏"的说法（F12、F13）不应出现在体验中。
3. [v0.3] 系统应在结尾提供 "What is real" 页：说明人物和台词是虚构的，列出史实句、来源、纹样为自绘，并标出哪些是"一种说法"。
4. 体验中不应出现福娃形象或名称、博物馆照片、讲解视频的画面或声音。

### Requirement 8：声音

**User Story:** 作为用户，我想要能带来氛围的声音，同时能随时关掉。

#### Acceptance Criteria

1. 系统应只在用户按下"开始"之后播放声音，以符合浏览器自动播放限制。
2. 系统应在每一幕都提供可见的静音开关，并记住用户的选择。
3. 所有声音应为自制、程序合成或明确可商用的素材；演示视频同样不应包含无授权音乐。[v0.5] 本版全部声音都在浏览器里程序合成，没有录音（D-012）。
4. 关闭声音后，体验仍应完整可懂；关键信息不应只通过声音传达。
5. [v0.5] 台词一句一句出现，下一句应等上一句的阅读时间结束（按字数估算），每句下面配一声很轻的合成气声（D-012）。
6. [v0.5] 暂停时台词队列应停住；跳过一幕时，该幕还没出现的台词不再出现。
7. [v0.5] 已删除（原为配音加载失败时的退路；现在没有配音）。

### Requirement 9：无障碍与舒适

**User Story:** 作为对动效敏感或只用键盘的用户，我也想完整体验。

#### Acceptance Criteria

1. 当系统检测到 `prefers-reduced-motion` 时，应减少镜头移动和抖动，用淡入淡出代替大幅运动。
2. 全部流程应能只用键盘完成，焦点可见。
3. 文字与背景的对比度应满足 WCAG AA。
4. 用户应能随时暂停，并能跳过当前幕。

### Requirement 10：语言

**User Story:** 作为不懂中文的评委，我想看懂全部文字。

#### Acceptance Criteria

1. 体验中的全部文字（含开始画面、"What is real" 页）应为英文。
2. 本版不做中文切换（Alex 2026-11-21 决定，见 D-004）。文字应集中存放，不散落在代码各处，以便以后需要时再加语言。

### Requirement 11：运行与发布

**User Story:** 作为评委，我想点开链接就能体验，不用登录或安装。

#### Acceptance Criteria

1. 体验应为纯静态网页，不需要后端、账号或登录。
2. 体验应在最新版 Chrome、Edge、Safari、Firefox 的桌面端运行，并在主流手机浏览器上可用。
3. 在中端笔记本上，动画应保持流畅，目标 60fps。
4. 首次加载的资源总量应控制在可接受范围内（具体数值在 `design.md` 中确定）。
5. 一次完整体验应在 5 分钟内结束。
6. 体验应在评审期结束（2027-01-29）前持续可访问。

### Requirement 12：尊重

**User Story:** 作为可能经历过失去孩子的用户，我不希望这段历史被拿来猎奇。

#### Acceptance Criteria

1. 体验中不应出现婴儿遗体、骨骼或血腥画面。
2. 恐怖手法只应用于第一到第三幕的进入与转折；第四、五幕应以温和为主。
3. 文案不应拿孩子的死亡开玩笑或制造惊吓。
